## Cel update'u

Dodać ręczny eksport i import kopii danych jako plik ZIP dla aplikacji mobilnej.

Ten etap domyka praktyczny backup lokalnego MVP bez wprowadzania jeszcze kont użytkownika, backendu, synchronizacji ani chmury.

## Zakres wdrożony

- dodano sekcję `Kopia danych` w zakładce `Bezpieczeństwo`
- użytkownik może wyeksportować dane do pliku `zenifi-backup-YYYY-MM-DD-HH-mm.zip`
- eksport używa `expo-file-system`, `expo-sharing` i `fflate`
- import używa `expo-document-picker` i kopii pliku do cache
- ZIP zawiera:
  - `manifest.json`
  - `data.json`
  - pliki załączników pod `attachments/<attachmentId>/<filename>`
- `data.json` przenosi dane finansowe bez lokalnych `fileUri`
- manifest ma pola przygotowane pod przyszłe szyfrowanie i chmurę, ale obecny tryb szyfrowania to `none`

## Reguły importu

- import scala dane z lokalną bazą zamiast kasować obecny stan
- rekordy o tym samym `id` są aktualizowane tylko wtedy, gdy importowany `updatedAt` jest nowszy
- nowe rekordy są dopisywane
- konflikt kategorii po nazwie mapuje kategorię na lokalną, jeśli typ jest ten sam
- konflikt kategorii po nazwie z innym typem dodaje sufiks ` (import)`
- transakcje i budżety są importowane po remapowaniu `categoryId`
- załącznik bez pliku w ZIP-ie jest pomijany i trafia do ostrzeżeń importu

## Granice bezpieczeństwa

- backup nie przenosi PIN-u
- backup nie przenosi ustawień biometrii
- backup nie przenosi sekretów z `SecureStore`
- pierwsza wersja ZIP-a nie jest szyfrowana
- użytkownik powinien traktować plik ZIP jak wrażliwy plik z danymi finansowymi

## Weryfikacja

- `npm run typecheck` przechodzi
- `npm run lint` przechodzi
- manualny smoke test eksportu/importu na urządzeniu pozostaje do wykonania

## Ograniczenia

- nie dodano testów jednostkowych, bo repo `finanse-app` nie ma jeszcze skonfigurowanego runnera testów
- Expo dev server nie wystartował w środowisku Codexa przez zajęte porty `8081` i `8082`, więc manualny test musi być wykonany osobno
